case study · trading intelligence

Token Research Report Bot

Problem. Checking a token means hopping between five sites and still missing contract risks. Traders want one trustworthy answer in seconds.

What I built. A Telegram command that fuses CoinGecko markets, the deepest DexScreener pool, a GoPlus security check (honeypot, mint rights, taxes, owner holdings) and filtered headlines into one rich report card — then writes a cautious verdict. If any source fails the card ships degraded and says so.

  • LLM verdict is grounded in fetched facts only, validated, with a deterministic template fallback
  • Primary APIs retry ×3; enrichments degrade gracefully — the report never dies mid-demo
  • Isolated demo endpoint answers over HTTP without touching real chats

03

case study · lead pipeline

Lead Capture → Enriched CRM

Problem. Small businesses lose leads in inbox chaos: no scoring, duplicates, zero instant follow-up.

What I built. Consent-based form → validation → 7-day dedupe on email hash → enrichment (company inferred from work domain) → LLM intent score 0–100 with a deterministic rule-score fallback → exact-schema Google Sheets row + instant tiered Telegram alert (🔥A / ⚡B / 🧊C) explaining the "why".

  • Consent enforced in code — the pipeline refuses to run without it
  • Sheet append failing never blocks the owner alert (error branches everywhere)
  • Demo mode processes a full lead while writing nothing to real state

case study · AI content ops

Review Summarizer

Problem. Shop owners drown in raw reviews and never extract what matters: recurring complaints and praise worth acting on.

What I built. One webhook: messy reviews in → digest out. Deterministic heuristics compute the rating split and themes first (one vote per review per theme, polarity from average rating of mentions); the LLM only writes the verdict and a suggested public reply, returning strict validated JSON.

  • Runs end-to-end with the AI completely off — mode shown honestly in the footer
  • Junk rows skipped and counted; empty payloads get a friendly usage note
  • The cheapest project here to run: zero external data sources

case study · client support

Client Support Chatbot

Problem. Clients ask the same ten questions; founders burn hours answering them — and chatbots that hallucinate prices make things worse.

What I built. A Telegram bot that answers from an owned knowledge base first (free, instant, deterministic retrieval with tag-boosted scoring). Only unknown questions go to an LLM, grounded with the full KB and strict system rules. Every reply is honestly tagged 📖 FAQ / 🤖 AI-assisted / 📮 human.

  • Escalation detection ("human", "agent") hands off gracefully
  • Channel-agnostic brain — swap to WhatsApp Cloud API by changing trigger nodes only
  • /demo command replays a canned question through the real pipeline

06

case study · the original

Smart Money Alert Bot

Problem. Retail traders see whale moves hours late — after the alpha is gone. Most "whale bots" spam noise: airdrops, wraps, and random transfers all look like trades.

What I built. Real-time Telegram alerts when 8+ hand-vetted smart-money wallets make a ≥$100K trade on Ethereum. Alchemy push webhooks (not polling), HMAC-SHA256 signature verification, leg-pairing trade classification that drops airdrops/self-transfers/stable-swaps, quote-leg valuation that prices unlisted tokens correctly, a $100K gate with 24h dedupe — and an AI one-liner grounded in fetched facts only, with a template fallback.

  • Proven under double-failure: CoinGecko AND the LLM killed simultaneously — the alert still delivered (stale price marked ≈, template sentence)
  • 6 classification fixtures green: buys, sells, unlisted-token buys valued via quote leg; forgeries silently rejected
  • Every alert ships with inline buttons: Dexscreener chart, Etherscan tx, Arkham wallet
  • Watchlist is curated evidence: every wallet machine-verified on-chain with public sources
