# 🔍 Token Research Report Bot

Type `/research PEPE` in Telegram → ~20s later you get a rich report card:
live price + 24h move, market cap/volume/rank, deepest DEX pool (liquidity,
volume, txns), a GoPlus security check with scam-pattern flags, matching
headlines, and a plain-English verdict.

**The verdict never dies:** if the LLM call fails, times out, or returns
garbage, a deterministic template verdict built from the same facts ships
instead. The demo path (`[DEMO]` tag) is fully isolated from real state.

## How it works (plain language)

1. **Trigger** — Telegram command, or a `POST /webhook/token-research/demo`
   webhook that answers straight back over HTTP (nothing touches your chats).
2. **Find the coin** — CoinGecko `/search` resolves the symbol; exact symbol
   match wins over fuzzy matches.
3. **Pull facts** — CoinGecko markets (price/cap/volume), DexScreener
   (deepest liquidity pool + contract address), GoPlus security (honeypot,
   mint rights, taxes, owner holdings) keyed by that contract, CoinDesk RSS
   filtered to relevant headlines.
4. **Score & speak** — one Code node aggregates everything into a report card
   and builds an LLM prompt from *only those facts*. The LLM writes a 2–3
   sentence cautious brief. A validator checks length/sanity; on any failure
   the template verdict (same facts, plainer words) is used.
5. **Deliver** — formatted Telegram HTML, or HTTP response for demos.

## Architecture

```
Telegram /research ─┐
                    ├─► Parse ─► Fetch search ─► Pick coin ─► Fetch markets ─┬─► Fetch dex ─► Prep refs ─► Fetch security ─┐
POST /demo webhook ─┘                                                       └─► Fetch headlines ──────────────────────────┼─► Aggregate ─► LLM ─► Validate/fallback ─► Is demo? ─► reply | send
```

Node map (Code nodes ↔ tested logic):

| n8n node | Source in `lib/logic.js` |
|---|---|
| Parse command | `parseCommand` |
| Pick coin id | `pickCoinId` |
| Prep enrichment refs | `pickDex`, `CHAIN_IDS` |
| Aggregate research | whole lib → `buildReport` |
| Validate LLM or fall back | `applyLlmSummary`, `esc` |

The workflow JSON is **generated** by `node build-workflow.js` from
`lib/logic.js` — the exact code the fixtures test is what runs in n8n.
No copy-paste drift. Re-run the build after editing logic.

## Reliability

- Primary lookups (search/markets): timeout 15s, retry ×3 @5s.
- Enrichments (dex/security/news): retry ×2, `onError: continue` — the report
  always ships, degraded cards say so ("partial data").
- LLM: no retry (cost control), 12s timeout, output validated (20–1200 chars);
  fallback = deterministic template. Fixture `llm-failure` proves it.
- Demo requests bypass Telegram entirely and answer via webhook.

## Free tiers used

CoinGecko free API · DexScreener public API · GoPlus Security public API ·
CoinDesk RSS · Telegram Bot API. Optional paid exception: your own LLM key,
per-call, stored only in n8n Credentials.

## Import & configure (5 min)

1. n8n → Workflows → Import from File → `workflows/token-research.json`.
2. **Telegram nodes**: select your existing bot credential (same one the Smart
   Money bot uses).
3. **Call summary LLM node**: attach a *Header Auth* credential —
   name `LLM API`, header `Authorization`, value `Bearer <YOUR_KEY>`.
   Adjust `url`/`model` if your provider isn't OpenAI-compatible.
4. Activate. In Telegram send `/research BTC`.

## Run the demo

```bash
curl -X POST https://<your-n8n>/webhook/token-research/demo \
     -H "Content-Type: application/json" \
     -d '{"text":"/demo PEPE"}'
```

Returns the full HTML report card with a 🧪 [DEMO] footer. No chat messages,
no dedupe state touched.
